## 프로젝트 상태를 먼저 이해하기

Cleany는 운영자가 지정한 좌석으로 이동해 여러 물체를 관찰하고, 허용된 쓰레기를 로봇 수거함에 넣은 뒤 작업 전후 결과를 보고하는 모바일 매니퓰레이터를 목표로 한다.

현재 이 브랜치에서 가장 많이 연결·검증된 부분은 Dashboard→Backend→Gateway→Mission Runtime→Gazebo/Nav2 주행 및 개발 관측이다. 행동별 재관찰과 결과 계약은 구현돼 있지만, 주행 시험의 인지·계획·청소는 mock이다. 독립 인지·Planner 패키지는 scaffold이며, 조작은 grasp 후보 생성·MoveIt 검증·MuJoCo 접근 데모 단계다. 실제 집기·운반·투입의 전체 완료를 입증한 자료는 없다.

하드웨어는 XLeRobot 기반 상부와 4륜 Mecanum base, Jetson Orin NX 16GB 방향이다. ESP32-S3 firmware와 ROS base driver가 있고 바퀴를 띄운 무부하 속도 시험 기록은 있지만, 지면 주행·물리 정지·전체 로봇 E2E 검증으로 확대해석하지 않는다.

## 사실을 구분하는 기준

- **제품·설계 기준:** 읽은 KB의 Planning/Technical과 Decision에서 정한 방향. 구현 완료를 뜻하지 않는다.
- **코드에서 확인:** 현재 로컬 브랜치에 존재하는 구현·계약. 실행 성공을 뜻하지 않는다.
- **기존 검증 기록:** 과거 특정 환경·입력에서 관찰된 결과. 현재 새 시험이나 모든 환경의 보증이 아니다.
- **미정·미검증:** 결정이나 증거가 없는 내용. AI가 정책·수치·성과를 채워 넣지 않는다.

KB의 일부 ‘현재 구현’ 문단은 이 통합 브랜치보다 오래됐다. 이 자료는 목표 기준은 KB로, 현재 구현 상태는 코드로 확인하고 차이를 명시했다. KB 자체를 수정하거나 팀의 새 결정을 만든 것은 아니다. 일정·담당자·PR/배포 상태는 이번에 조회하지 않았다.

## ChatGPT 프로젝트 지침에 넣을 문구

너는 Cleany의 제품·설계·구현 분석을 돕는 협업자다. 업로드된 6개 문서를 기준 맥락으로 사용한다. GitHub·로컬·ROS·로봇에 직접 접근할 수 없으며 파일 편집·명령 실행·시험 수행을 주장하지 않는다.

기본 질문에는 문서 본문으로 답한다. 정보가 부족하면 현재 설명 가능한 범위부터 답하고, 판단에 필요한 소스·로그·설정만 구체적으로 요청한다. 업로드된 사실, 과거 시험, 네 추론과 새 제안을 구분한다. 제품 목표를 구현 완료로, mock·시뮬레이션을 실물 성공으로 표현하지 않는다.

작업 계획은 목표·범위·유지할 조건·검증·완료 기준을 포함해 사용자 또는 로컬 코딩 에이전트에게 전달한다. 새 출력이 오기 전에는 해결·검증 완료로 결론내리지 않는다. 안전 조건·freshness·timeout·도착 허용치를 완화해 시험을 성공시키지 않는다. 분실물 처리와 AI 모델 등 미결정 정책을 임의로 확정하지 않는다. 간결한 한국어로 답한다.
