# 보정된 CAD 파지 모델

`freecad_calibrated`는 검증된 FreeCAD 배포의 외형과 충돌 캐시를 현재 모터
좌표에 연결한다. 참조 뷰어의 `reference_only` 설정은 변경하지 않는다.
`cad_grasp.json`의 `cad_binding_file`은 원본 모델, 카메라 보정, 기존 캐시의
해시와 좌표 대응을 보존한다. 이미 보정한 관절 원점은 고정된 카메라 보정
모델에서 가져온다. 메시를 다시 맞추거나 고정턱 보정을 추가하지 않는다.

Jetson의 `cad_grasp.json`은 `collision_mesh_overrides`로 단순화한 충돌 메시를
선택한다. 키는 원본 GLB의 SHA-256, 값은 대체 GLB의 SHA-256이다.
프로파일을 생성할 때 충돌 요소의 원본 URI를 찾아 대체 파일의 해시를 확인한다.
시각화에는 원본 CAD를 사용한다. 체결 구멍 단순화 대상은 손목 카메라 마운트, 그리퍼 판,
캠 혼과 서보 부품에 있는 지름 약 2.05~5.20 mm의 체결 구멍이다.

긴 팔 튜브의 충돌 형상은 모서리가 있는 사각 기둥이다. 이전 볼록 형상을
포함하며 추가 돌출은 0.53 mm 이내다. 중앙 기둥과 팔 연결부의 단순화된 볼록
형상은 기존 형상을 포함하며 돌출 상한은 0.25 mm다. 그리퍼 몸통의 판과
서보, 네 손끝 뒤 지지대는 기존 표면과의 양방향 거리 상한 0.1 mm를 적용한다.
손끝의 물체 접촉 패드에는 기존 형상을 사용한다.

| 계산 | 입력과 책임 |
|---|---|
| 모터와 제어기 | 기존 14개 관절 이름과 rad 좌표, 보정 범위를 유지한다. |
| 팔과 헤드 | 기존 `q_CAD = scale × q_motor + offset`을 URDF 원점과 동축 mimic 관절로 표현한다. CUDA가 지원하는 축 정렬을 위한 고정 프레임은 원래 CAD 몸체 좌표를 복원한다. |
| 대칭 집게 | 모터의 최대 열림 0도와 닫힘 160도를 CAD의 열림과 닫힘 끝점에 대응시킨다. 기존 `solve_linkage`의 원 교점과 조립 분기로 종속 관절 16개를 계산하며 모터 명령 인터페이스를 만들지 않는다. |
| GPU IK | `curobo_ik_moveit`와 `cad_cached`가 기존 primitive 캐시를 사용한다. CPU IK fallback은 사용하지 않는다. |
| 충돌 판정 | `cleany/CalibratedCADFCL`이 각 검사 상태의 손가락 연동을 다시 계산한 뒤 기존 CAD 충돌 구현에 전달한다. GPU의 직접 전체 충돌 검증 경로는 이 모델을 거부한다. |
| 대상 물체 접촉 | 실제 손목과 손가락 몸체만 touch links에 포함한다. 팔과 지지대는 포함하지 않는다. |

`CLEANY_CAD_LINKAGE_JSON`은 launch가 준비된 URDF의
`cleany_cad_calibration` 속성에서 전달한다. 연동 계산에 실패하면 해당 상태를
충돌로 판정하며, 요청자가 전달한 상태는 수정하지 않는다. 자기 충돌용
`cad_self__`와 외부 충돌용 `cad_world__` 구분, 선언된 enclosure의 solid 처리와
ACM은 기존 배포 구현을 따른다. 기존 제어 모델과의 충돌 구현 혼용을 피하기
위해 재사용한 CAD 구현의 C++ namespace를 분리한다.

운영 모델에서 외부 충돌과 자기 충돌 형상이 다른 부품은 양쪽 그리퍼의 구동 링크 네 개다.
운영 프로파일의 `shared_world_collision_links`에 지정된 베이스, 헤드, 팔 링크는 두 검사에
같은 외부 충돌 형상을 사용한다. 네 구동 링크는 자기 충돌에 원본 STL 표면을 사용한다. 기존 convex enclosure는
오목한 굽힘 사이의 빈 공간을 메워 조기 충돌을 발생시킨다. 외부 물체에 대해서는
기존 solid enclosure를 유지한다. 링크 사이 충돌을 ACM으로 허용하지 않는다.

기존 SRDF의 기계 접합부 허용은 형상이 없는 호환 프레임에서 실제 CAD
몸체로 옮긴다. 기존 두 턱의 닫힘 접촉 허용은 대칭 집게의 두 tip에 연결한다.
그리퍼 구동 링크 L/R 사이의 충돌은 허용하지 않는다. 접근, 닫기와 들기 등
단계별 검사를 수행할지는 기존 수거 프로파일의 설정을 따른다.

`configs/robot/cad_gripper_endpoints.json`은 양쪽 끝점 대응을 관리한다. 현재
모터 범위 2048~3868 tick, 즉 159.9609375도는 유지한다. CAD 원본 BREP는
144~145도 사이에서 구동 링크 간섭이 시작되며, 기존 STL은 144도에서
약 0.014 mm의 보수적인 간섭을 보고한다. 두 형상 검사에 통과하는 최대 정수
각도인 CAD 143도를 열림 끝점으로 사용한다. 이 값은 모터의 개방 제한이 아니다.
중간 모터값을 두 끝점 사이 CAD 각도로 선형 대응한 뒤 비선형 링크를 계산한다.

집게 폭 제어와 CAD 운동학 연동은 별개다. 이 전환은 이전에 복원한 개구 폭
곡선을 다시 적용하지 않는다. 끝점 보간은 실측된 모터/캠 기어비나 중간 개구
폭 보정이 아니므로 실제 중간 손가락 위치의 정확도를 보장하지 않는다.

`cad_binding_file.motion_validation.ready`가 true가 아니면 쓰기 가능한
`real_control.launch.py`는 하드웨어 노드를 만들기 전에 거부한다. 프로파일
생성과 별도 domain의 FK, 충돌, 계획 및 GPU 검증에는 모터 드라이버가 필요
없다. 이 플래그를 수동으로 바꾸어 충돌 실패를 우회하지 않는다.

## Jetson 파지 후보의 OctoMap 검사

Jetson Orin에서 `cleany_moveit_collision`을 `-DCLEANY_ENABLE_CUDA_OCTOMAP=ON`으로
빌드하면 실물 MoveIt의 깊이 지도 실행에 `/check_grasp_octomap`을 등록한다. 서비스는
현재 장면과 OctoMap을 읽기 잠금한 상태에서 최대 64개 IK 자세를 검사한다.
지도 또는 충돌 형상이 바뀌면 CUDA 데이터를 갱신한다. 지원하지 않는 장면이나 CUDA
오류에서는 선택기가 기존 MoveIt 검사를 사용한다.

`/grasp_selection_server`의 `grasp_octomap_mode`은 `off`, `compare`, `on`을 받는다.
`compare`는 같은 지도에서 MoveIt의 OctoMap 결과를 비교한다. 두 검사가 일치하면
GPU에서 겹침이 확인된 후보를 제외한다. 결과가 다르면 전체 배치를 MoveIt으로 다시 검사한다.
`on`은 비교 호출을 생략한다. GPU 검사에서 충돌이 없었던 후보의 최종 자세와 경로는
MoveIt에서 전체 장면을 기준으로 검사한다.
