# 실물 매니퓰레이션 조작 경로 및 파라미터 규격

본 문서는 실물 로봇(Jetson Orin NX)에서 수거 파이프라인(`physical_grasp_selection_server`)을 운영할 때 적용되는 기구학적 파라미터, 접근 보정, 다단계 접근 준비 자세 및 안전 계약을 설명합니다.

> [!IMPORTANT]
> 실물 파지 선택기는 `physical_grasp_selection_server`로 실행되며, 기존 시뮬레이션용 `grasp_selection_server`와 동일한 네임스페이스에서 동시에 기동하지 않습니다.

## 1. 파지 목표 추가 삽입 (Approach Insertion Offset)

물체를 그리퍼 깊숙이 안정적으로 물도록 하기 위해 접근 방향으로 추가 이동을 적용합니다.

- **설정 파일**: `configs/robot/collection_motion.yaml`
- **파라미터**: `grasp_approach_offset_m: 0.020` (20mm)
- **동작 원리**:
  - 생성된 파지 후보의 접근 방향 벡터를 따라 최종 TCP 목표점을 **20mm 전진**시킵니다.
  - TCP의 기구학적 정의나 그리퍼 닫힘 방향 보정은 변경하지 않습니다.
  - 보정된 최종 목표점을 기준으로 IK, 충돌 검사, 그리퍼 닫힘 여유 공간 및 경로 계획을 재검증합니다. (도착 후 맹목적인 추가 이동 없음)
  - 원래 깊이로 되돌리려면 이 값을 `0.0`으로 설정합니다.

## 2. 다단계 접근 준비 자세 (Pregrasp Multi-Step Fallback)

파지 직전의 접근 준비 위치(Pregrasp)에서 관절 한계 초과나 특이점으로 인해 IK가 실패하는 현상을 방지하기 위해 다단계 거리 대체 정책을 지원합니다.

- **설정 파라미터**:
  - `pregrasp_offset_m`: 기본 준비 거리 (기본값: `0.08` m = 8cm)
  - `pregrasp_fallback_offsets_m`: 단계적 대체 준비 거리 목록 (수거 프로파일: `[0.06, 0.04]` = 6cm, 4cm)
- **동작 순서**:
  1. 먼저 **8cm** 거리에서 준비 자세 IK 및 충돌 검사를 수행합니다.
  2. 8cm에서 해를 찾지 못하거나 허용 각도 오차(30도)를 초과하면 **6cm** 자세를 검사합니다.
  3. 6cm에서도 실패하면 최종적으로 **4cm** 자세를 검사합니다.
  4. 앞선 거리에서 유효한 경로가 확보되면 이후 짧은 거리는 검사하지 않고 조기 종료합니다.
- **실제 거리 (추가 삽입 20mm 포함 시)**:
  - 준비 자세와 보정된 최종 파지 목표 간의 실제 거리는 각각 **10cm, 8cm, 6cm**가 됩니다.

## 3. 들어올리기 단일 높이 보정 (Single-Step Lift Correction)

물체를 집어 올린 후 하중이나 서보 모터 처짐으로 인해 목표 높이에 미달하는 경우를 보정합니다.

- **파라미터**: `lift_height_correction_enabled: true`, `lift_height_correction_step_m: 0.005` (5mm 단위)
- **동작 방식**:
  - 목표 높이와 실측 관절 FK(순기구학) 높이를 비교하여 부족분을 계산합니다.
  - 부족한 높이를 5mm 단위로 올림(Ceil)하여 **단 1회만** 추가 상승 경로를 계획 및 실행합니다.
    - 예: 0.011m(11mm) 부족한 경우 0.015m(15mm) 추가 상승
  - 반복 보정 루프로 인한 지연을 방지하기 위해 1회 보정 후 남은 오차는 로그에만 기록하고 다음 파이프라인(물체 보유 확인 및 복귀)으로 진행합니다.

## 4. 놓기 후 후퇴 및 동기 복귀 충돌 검사

- **물체 놓기 후 안전 후퇴**:
  - 측정된 관절 FK 위치에서 후퇴 경로를 계획하되, 첫 모터 명령은 팔이 유지 중이던 기존 목표값을 이어받아 불필요한 흔들림을 방지합니다.
- **동기 복귀 충돌 검사 (Synchronized Return)**:
  - 팔 복귀(Return Home)와 그리퍼 닫기가 동시에 일어나는 복귀 경로는 전송 직전에 전체 로봇 상태 및 옥토맵을 대상으로 충돌 검사를 수행합니다.
  - 충돌 가능성이 감지되면 `hardware_collision_validation_failed` 이벤트와 함께 상세 접촉 링크를 남기고 전송을 차단합니다.

## 5. GPU 자원 조율 및 우선순위 (GPU Work Lock)

AnyGrasp(비전)와 cuRobo(모션) 간의 GPU 충돌을 방지하기 위해 파일 락(`gpu-work.lock`)을 운용합니다.
- **실제 요청 최우선**: 사용자의 파지 요청(Foreground Demand)이 백그라운드 모델 예열보다 항상 우선합니다.
- **양보 메커니즘**: 진행 중인 cuRobo 예열 작업은 실제 요청이 감지되면 다음 CUDA 단계 경계에서 즉시 GPU를 양보합니다.
